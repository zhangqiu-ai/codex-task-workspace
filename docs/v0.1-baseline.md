# v0.1 开发基线 · 第一切片

2026-09-13，根据「Codex插件是什么\\Seeder」讨论及本次明确需求收敛。原讨论里的完成百分比由后续“事实状态 + 证据”取代。

## 产品边界

Workspace → Project → Task → Session。Task 是长期工作目标，Session 是执行证据。一个 Task 只有一个主 Project；Project 可无 Git 仓库。当前本地工作区有多个 Project；数据库预留 Workspace 实体，第一切片只操作一个本地 Workspace。

- My Work 跨项目看板：待办 / 进行中 / 阻塞 / 完成，列内纵向卡片。
- Global Inbox 收纳尚未归类的 Session；创建 Task 必须指定 Project，避免虚构 Inbox 项目。
- Focus 是多个任务的显式标记；Active Task 是工作区唯一当前选择。后台 Hooks 不因全局选择变化自动挪动会话，避免并行会话误归属。
- Task↔Session 独立关系表；v0.1 一个 Session 最多关联一个 Task，可显式移动。按任务保存结构化 AI 评估及证据，稳定计算推荐分；缺少评估时明确使用时间排序回退。会话长度不作为降权理由。
- Continue Task 读取最新 SQLite 事实，返回项目/任务记忆、排序会话、Git 引用与可复制提示词；返回可恢复的 Session ID，不声称已启动 Codex。由调用方执行受支持的续接能力。

## 存储契约

```text
Session 元数据 / 用户与 AI 提交的证据
                  ↓
       SQLite（唯一系统事实源）
                  ↓
project-memory.md / task-memory.md（可重建视图）
                  ↓ 用户审阅 Promote 草稿
       AGENTS.md / ADR / 架构文档
```

默认数据目录 `~/.local/share/codex-task-workspace`，可由 `TASK_WORKSPACE_HOME` 覆盖。不会写入 Codex Core 的 memories，不拷贝原始 transcript。Memory Fact 含 scope、kind、authority、evidence、confidence、status、superseded_by；替代保留旧记录。Markdown 只从 SQLite 渲染，失败可重建；Continue 总是直接读数据库。Promote 第一切片仅生成待审阅内容和建议目标，不自动修改权威文件。

## 本切片可交付

manifest、SQL schema、TypeScript domain types、stdio MCP、同域本地 HTTP API、Task Board、Hooks 元数据采集骨架。覆盖创建/更新任务、Focus/Active、关联/移动会话、记忆新增/替代、排序、上下文续接、Git branch/commit 显式关联、Hook Health。使用 Codex 作为 AI：skill 指导模型提交带证据的结构化分析；没有独立模型服务、后台自动总结或付费调用。

Hook Health 的“已接收”只证明采集器收到事件；未知/陈旧状态不会显示为宿主安装成功。Hooks 格式参照本机 Codex 源码，宿主安装和真实生命周期回调另行验证。UI 是独立 localhost 看板，本切片不集成原生侧栏或声称 MCP Apps 已接入。

## 明确不做

云同步、团队协作、移动端、复杂统计、跨账号历史导入、全量 transcript 解析、后台模型调度、自动 Promote、Git 提交/切分支、插件市场发布。第一切片在本地仓库验证，不改现有项目或安装配置。

## 验收

真实 SQLite 持久化和约束；任务和会话闭环；Memory 替代后重建；排名证据与回退；Continue 上下文；Hook 重复事件幂等与未知健康；MCP initialize/tools/list/tools/call；HTTP API 错误及跨源保护；看板浏览器交互。
