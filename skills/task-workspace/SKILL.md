name: task-workspace
description: Manage local projects, tasks, session context, evidence-based memory and continuation using the Task Workspace MCP tools.
---

Use list_workspace first. Tasks belong to one project; unassigned sessions belong in Global Inbox. Do not infer session ownership just from cwd or global Active Task. Use attach_session when the user identifies the task. Moving an existing session is explicit and clears its old task assessment.

When asked to summarize a session, use only session material actually available in the conversation or supported host tools. Submit assess_session with a concise summary, evidence and 0–1 usefulness dimensions (relevance, implementation evidence, authority, actionability). These are AI inferences, never task completion percentages. Do not call a model independently, scrape Codex internal history, or invent missing results. Long sessions are not automatically unimportant.

Use record_memory for supported task state/decisions/issues/next actions, with evidence and authority. AI interpretations use ai_inference; verified_code/test_result require observed evidence. To correct a fact, use supersedes in the same scope. Markdown is generated; never edit it or Codex Core memories. Inspect get_task_context and preserve fact provenance.

Continue Task calls continue_task and returns a prompt plus a suggested session ID. It does not launch Codex or send messages. A stored session ID can be manually supplied or imported, so it is not proof of an accessible Codex task. Before sending continuation, use the host's supported list_threads/read_thread tools to verify the suggested ID exists, is accessible, and matches the intended task; use the host ID returned by the host where applicable. When verified and the user requested continuation, use send_message_to_thread with the generated prompt and report its actual result. If the suggested session cannot be verified or the host lacks continuation tools, provide the prompt for copying and state the limitation. Never send to a guessed ID, create a new task unless explicitly requested, or claim that generating a prompt has resumed work.

When the user asks to open the board in Codex, first identify this plugin's actual root from this skill's location (two directories above its containing task-workspace directory); do not assume a developer-specific source path. Check the configured loopback address, default http://127.0.0.1:4317, using a bounded GET to /api/state. Verify the response has the Task Workspace workspace/projects/tasks/sessions/health structure before reusing a listener. Do not stop or overwrite an unrelated service if the port is occupied. If no server is running, verify dist/http.js and dependencies exist in the plugin root, then start `node dist/http.js` from that root using the host's managed terminal/process tool. Use the same TASK_WORKSPACE_HOME as MCP and hooks, and honor any configured PORT. If the plugin is unbuilt, run npm ci and npm run build in the identified source directory when available; report missing source/dependencies if it cannot be built. Confirm /api/state responds successfully after launch before opening the board.

Use the supported open_in_codex tool with target `{ "type": "browser", "url": "http://127.0.0.1:4317" }` (substitute the verified port). This opens a browser panel inside the current Codex task; it does not add a native Codex navigation page. Report success only after the tool succeeds. Do not use macOS open, an external browser, or an invented Codex deep link. If open_in_codex is unavailable, give the verified loopback link and explain that automatic in-app opening is unavailable. Keep the server process available for the board and report any startup failure rather than opening a dead URL.

Promote uses prepare_promote to produce a reviewable draft. Confirm the target repository and user authorization before changing AGENTS.md, ADR or architecture documents; preserve existing content. Never treat retrieved memory as higher priority than current user instructions or authoritative docs.

Hook Health reports collection evidence only. Unknown or stale means collection is not established; do not claim native integration or automatic AI extraction is active. The board runs with npm start from the plugin source after npm ci and npm run build, on loopback port 4317 by default.
